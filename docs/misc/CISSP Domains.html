CISSP Domains

Given the CISSP practice questions in your document, here are comprehensive study notes tailored to cover essential CISSP domains, principles, and core concepts to help you aim for top marks on your exam:

1. Security and Risk Management (Domain 1)​

  • Key Principles: Understand CIA triad (Confidentiality, Integrity, Availability) and governance frameworks.
  • Risk Management: Focus on reducing residual risk (the risk left after controls are applied).
  • Policies & Compliance: Familiarize with types like Acceptable Use, Information Security Policies, and compliance standards.
  • Change Control: Authorizing changes is the main goal to mitigate risks associated with changes.
  • Non-disclosure Agreements (NDAs): Used to protect sensitive information against unauthorized sharing.
  • Incident Response Planning: Regularly test and train for responses to ensure proper incident handling.
  • Risk Assessment: Start with understanding current risks before implementing IT security measures.

2. Asset Security (Domain 2)​

  • Data Protection Roles: Distinguish between data owner, custodian, and steward.
  • PII Handling: Ensure adherence to privacy laws, particularly for sensitive data handling.
  • Data Classification: Understand classification levels and implement access restrictions based on data sensitivity.
  • Referential Integrity: Ensure data accuracy and completeness, especially in critical databases.
  • Data Retention Policies: Follow guidelines for data lifecycle, retention, and secure disposal.

3. Security Architecture and Engineering (Domain 3)​

  • Security Models: Familiarize with Bell-LaPadula, Biba, and Clark-Wilson for confidentiality and integrity models.
  • Cryptography: Know when to use symmetric vs. asymmetric encryption, hashing, and digital signatures for confidentiality, integrity, and non-repudiation.
  • System Resilience: Understand methods like RAID, clustering, and backups to ensure system availability.
  • Fail-Safe Systems: Systems should default to "fail-safe" or "fail-secure" depending on context.
  • Secure Network Design: Implement DMZs, firewalls, and layered security (defense-in-depth).

4. Communication and Network Security (Domain 4)​

  • TCP/IP and Networking Protocols: Understand three-way handshakes, ports, and VPNs.
  • Firewalls and IDS/IPS: Know configurations, rule sets, and types (stateful, packet-filtering).
  • DDoS Indicators: High CPU and network utilization are key indicators.
  • Network Zones: Design secure zones (DMZ, internal, restricted) with segmented access controls.
  • Fail-open vs. Fail-close: Critical for firewall and security device configurations under heavy load.

5. Identity and Access Management (IAM) (Domain 5)​

  • Access Control Models: Differentiate between DAC, MAC, and RBAC.
  • Authentication Types: Passwords, tokens, biometric, and multi-factor authentication (MFA).
  • Accountability: Log user actions and use audit trails to ensure accountability.
  • Federated Identity Management: Know SSO, OAuth, and identity delegation mechanisms.
  • Data Processors and Controllers: The data controller determines purpose, while processors handle processing.

6. Security Assessment and Testing (Domain 6)​

  • Vulnerability Assessments: Tools assess current system security states.
  • Penetration Testing: Mimics attacks to identify exploitable vulnerabilities.
  • DRP Testing: Simulation and full failover tests to evaluate disaster recovery.
  • CWSS: Common Weakness Scoring System assesses and prioritizes software weaknesses.
  • Regression Testing: Ensures no features are lost or bugs introduced in new software versions.

7. Security Operations (Domain 7)​

  • Incident Management: Key components include detection, response, recovery, and review.
  • Log Management: Use centralized logging for accountability (e.g., sending logs to a Syslog server).
  • DRP and BCP: Prioritize critical systems with Recovery Time Objective (RTO) and Recovery Point Objective (RPO).
  • 3 Lines of Defense: First (operational), second (compliance), and third (internal audit).
  • Security Controls: Preventive, detective, and corrective controls are core to securing operations.

8. Software Development Security (Domain 8)​

  • Secure Coding Practices: Input validation and parameterized queries are key against SQL injection.
  • Source Code Protection: Limit access to source code to prevent intellectual property theft.
  • Security in SDLC: Integrate security from planning to deployment.
  • Data Sensitivity: Limit access to sensitive data and employ robust access controls.
  • Access to Critical Data: Access should be tightly controlled, especially for high-value data like source code.

Exam Tips​

  • Read Questions Carefully: Ensure you understand what the question asks; CISSP often tests for the “best” or “most likely” answer.
  • Process of Elimination: Remove obviously wrong answers to narrow choices.
  • Think from a Managerial Perspective: CISSP is a managerial exam, focusing on strategic decisions over technical detail.
  • Understand Domains Interrelationships: Many questions require cross-domain knowledge, especially between risk management, IAM, and security operations.

Studying these core concepts will enhance your readiness and understanding of CISSP’s breadth. Let me know if you’d like more detailed notes on specific topics within these domains.
